Generate Your README

Pre-work · 2 minutes

Before you audit anything, get your M2 prototype summarised by Lovable and pushed to GitHub. This README becomes the input for every step below.

🔗 Open your M2 Lovable project
1
Paste this prompt into Lovable's chat bar
"Write a README for this project that summarises the hypothesis, scenario, key screens, user flow, and main build decisions. Save it as README.md and push it to my GitHub repository."
2
Open the README in GitHub
Confirm Lovable pushed README.md to your repo. Keep that tab open — you'll reference it throughout the chain.
⚠️
If Lovable says it can't push: check that your GitHub connection is still active under Settings → GitHub in your Lovable project. Re-link if needed, then re-run the prompt.
1

Audit Your M2 Prototype

Plan, Step 1 · 4 minutes

With your README open, audit your current M2 build against three lenses. You're naming the gaps your chain will close.

⛓️ Open the Prompt Chain Planner — Step 1: Audit
A
The Flow Gap
What are the 3–5 additional screens or modal states required to guide a user through a complete, end-to-end task? List them in the exact sequence you'll build them.
B
The Friction Audit
Where will the user encounter a data-load, an empty list, or a submission failure? Identify 3 specific points where you must hard-code loading / error / empty-state logic.
C
The Polish Audit
What is the one specific screen or UI element that's failing your visual standards? Pick one — Refine is a scalpel, not a hammer.
💡
Stuck? Paste your README into ChatGPT / Claude and ask: "Read this README and propose 3–5 missing screens, 3 friction points, and 1 UI element that would most benefit from surgical refinement." Use that as a starting point, then edit.
2

Draft Expand · Behavior · Refine

Plan, Step 2 · 7 minutes

Translate the audit into three prompts. Each one anchors to a distinct strategy — don't write three Expand prompts.

⛓️ Open the Prompt Chain Planner — Step 2: Draft
1
Prompt 1 — Expand (COT)
Use Image-Anchored COT Sequencing. Pair each new screen with a visual reference so the prompt focuses entirely on the navigation logic. Template: "Add a [Nth] screen: [what it shows]. Match the layout of the attached [reference] screenshot. Add a [Nth] screen: [what it shows]. Match the attached [reference] screenshot. Build navigation between all [N] screens."
2
Prompt 2 — Behavior (Constraint Grounding)
Hard-code the unhappy path. Define exactly how the system handles loading delays, missing data, and technical failures. Template: "Add a loading state with skeleton screens for [section]. Add an empty state for [scenario]: '[exact message]'. Add an error state for [failure case]: '[exact message]'. Maintain the same design language and tether all behavior strictly to these rules."
3
Prompt 3 — Refine (Reflection)
Force the AI to audit before it acts. Template: "Focus only on the [specific screen]. Start by listing the 3 biggest gaps in [design/spacing/logic] compared to the [reference brand] standard. Once identified, [add/move/resize component] to fix those gaps. Don't change anything else."
💡
Faster path: Paste your README + Step 1 audit into an LLM and ask: "Generate Expand, Behavior, and Refine prompts for this prototype using the templates above." Then edit the output for specificity. Don't accept the first draft.
📸
Visual anchors: for the Expand prompt, you need one screenshot per new screen. Grab them from Mobbin, your own product, or a competitor before you leave this phase.
3

Show and Swap Your Prompts

Peer Cold-Read · 10 minutes

Pair with a peer. Swap your Prompt Chain Planner doc link in chat. 3 minutes of silent reading per partner. No verbal context. No explanations. Confusion is data.

1
Sequence — did anything jump?
Did the partner spot a sudden jump or any confusion in the screen sequence? Did you understand exactly how the user gets from the first screen to the last, or was there a missing step?
2
Behavior — what's missing?
Is there a piece of error / loading / empty-state logic that might have been missed? What happens if data fails to load? Is there a Constraint Grounding rule for that?
3
Reusability — what's portable?
What's the strongest part of this chain that makes it reusable for other projects? Which part of the prompt structure was so clear that it could be used for a completely different app?

If your partner can't follow your chain in silence,
your prompts aren't reproducible.

Capture your partner's feedback in
03-prompt-chaining/swap-notes.md — one bullet per question. Edit your chain before the lab if anything broke.

Execute Prompt 1 — Expand

Lab · 12 minutes

Open your M2 Lovable project. Paste your Expand prompt + visual references. Build the new screens.

🔗 Open Lovable
1
Paste your Expand prompt
In Lovable's chat bar
Drag your screenshot(s) onto the chat. Hit enter. Watch the AI build screens A → B → C in strict sequence.
2
Verify navigation works
Click between old + new screens. If a button is broken or a layout is off, send a 1-sentence fix prompt — don't redo the whole chain.
3
Log P1 results
In your Planner Log: how many screens you now have, whether the design matched, what worked, what didn't, any fixes you made.
5

Execute Prompt 2 — Behavior

Lab · 12 minutes

Ground the AI in your loading / empty / error rules. Then manually trigger at least one unhappy path to verify.

1
Paste your Behavior prompt
Exact strings for empty + error states. Tether all behavior strictly to your rules.
2
Trigger an unhappy path
Search for a non-existent item. Disconnect your network. Submit an empty form. If your states don't trigger, send a 1-sentence fix — don't move on.
3
Log P2 results
In your Planner Log: did loading / error / empty trigger correctly? Did the AI follow your constraints, or drift?
⚠️
If the AI drifts: don't re-prompt the whole chain. Re-prompt only the specific rule that broke. "You ignored the empty-state rule for [section]. Re-apply: '[exact message]'."
6

Execute Prompt 3 — Refine

Lab · 10 minutes

Surgical steering. Force the AI to audit first, then act on the single UI element you targeted.

1
Paste your Refine prompt
The prompt should start with "list the 3 biggest gaps" before any change. The "Don't change anything else" line is your insurance policy.
2
Confirm the scope held
Click through every screen. The AI should ONLY have touched your targeted element. If anything else changed, revert and re-prompt with a tighter scope clause.
3
Log P3 results
In your Planner Log: which UI polishes applied, whether the rest of the build remained stable, or whether you had to steer it back.
🔁
Time left? Restart the cycle. Find the next flow gap → run a second chain (Expand → Behavior → Refine). Don't settle for one cycle if the prototype still feels incomplete.

Save PROMPTS.md and Push to GitHub

Lab close · 5 minutes

The chain is the deliverable. Save your three prompts + results as PROMPTS.md and push the project to GitHub.

1
Prompt Lovable to save + push
"Save my three prompts — Expand, Behavior, and Refine — along with the results I documented for each, as a PROMPTS.md file. Then push all current project files to my connected GitHub repository."
2
Verify in GitHub
Open your repo and confirm PROMPTS.md shows your three prompts + the result logs. This is what your teammates will see.
3
Add to your Living Prompt Pack
Open the Living Prompt Pack Builder and add this chain as a Chain Entry. Each cohort week, your pack grows — by M6 you'll have ~6 reusable chains.
