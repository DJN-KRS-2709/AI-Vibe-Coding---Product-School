Module 6 — Reference Card

M6 Frameworks Reference Card

The Iteration Mindset, the Metrics That Matter, the Three Layers of Analytics, the Strategic Analysis Prompt, and the Data-Signal-to-Fix patterns — one page, in the order you use them.

Every framework from Module 6 in the order you use them. Keep this open while you read your Lovable Insights, gather peer feedback, run your AI analysis, write your "based on the data..." prompt, and redeploy.

1. The Iteration Mindset — Three Levers

Shipping a vibe-coded product isn't the finish line; it's the start of the feedback loop. The job is to replace "I think" with "the data shows."

LeverWhat it answersWhy your gut can't
1. Feature Prioritisation Which 20% of your product drives 80% of the value? Every V1 has ghost features. Data tells you which features are anchors and which are dead weight.
2. Friction Identification Where are the leaks and dead ends in your UI? You know how the app works because you built it. Real users don't. Your bias is built in.
3. Hypothesis Validation Are users behaving the way you predicted in M2? Data is the only objective check on whether your solution is operating the way you engineered it to.

Rule: from this point forward, your intuition is just a hypothesis the data either proves or kills.

2. Metrics That Matter — 3–5 Signals, Not 50

Analysis paralysis is the biggest killer of V2. Narrow the lens to a handful of signals that map directly to your problem statement.

BucketQuestions it answersWhat "good" looks like for a V1
🚦 Engagement How many signed up? Which features are used most — and which are ghosts? The core flow event fires for >60% of new sign-ups.
🔁 Retention Do users return after their first session? Where do they drop off? Any second-session return at all. For most V1s, return rate ≠ zero is a win.
⚙️ Quality Page load < 3 seconds? Dead ends? Error rates? Bounce rate < 50%. No dead-end screens (every screen has a next-step CTA).
🎯 Impact Does behaviour match your M2 hypothesis? Your hypothesis-tied event (e.g. "invite sent") fires for the users who you predicted would send invites.

The North Star: does user behaviour confirm or contradict your original problem statement? If the data says no, your V2 isn't an update — it's a pivot.

3. The Three Layers of Analytics

Shipping is 50% of the job. The other 50% is architecting how you'll see friction before the user realises it's there.

LayerToolWhat it captures
1. Internal · Passive System Lovable Insights (built-in, free, on since M5 deploy) Surface engagement — active users, sessions, page views, click depth, bounce rate.
2. External · Passive Behavioural Google Analytics 4 (~10 min post-class setup) Deep-funnel signal — traffic sources, conversion paths, where users abandon flows.
3. Custom · Active Sentiment In-product capture wired to Supabase Qualitative data you own — star ratings, bug reports, feature requests, support tickets.

Rule: Layer 1 is today's lab. Layer 2 is the optional post-class extension. Layer 3 is the senior-PM move you make the moment you have a paying user.

4. The Strategic Analysis Prompt

The PM's new superpower: minutes to a synthesised, ranked backlog instead of days of CSV exports and pivot tables.

How it works

  • Old way · Manual Analysis. Export CSVs, build pivot tables, spend 6 hours writing a "findings" doc no one reads.
  • New way · AI-Powered Synthesis. Feed problem + hypothesis + metrics + feedback into an LLM. Get a ranked backlog in seconds.
  • The discipline. The AI provides the synthesis. You provide the conviction. Pick one finding. Not three.

The prompt — paste into ChatGPT / Claude / Gemini

I built a product to solve this problem: [problem statement].

My hypothesis was: [hypothesis].

Here are the metrics from my deployed product (Lovable Insights):
[paste Visitors / Page Views / Views Per Visit / Duration / Bounce Rate]

Here is the feedback I received from peer users in Slack:
[paste all comments — keep the 🐛 / 🤔 / 🤩 / 💡 labels]

Evaluate honestly:
1. Is this product solving the problem? What does the data suggest?
2. Where does my hypothesis appear confirmed vs contradicted?
3. What are the top 3 improvements, ranked by likely impact?
   For each, name the pattern: Persona Refinement / Visual Branching / Guardrail.

Be specific and grounded in the data I gave you. Do not invent metrics.

Verify: the AI's response is grounded in your inputs (no hallucinated metrics). Findings are ranked. Each is tagged with one of the three patterns below.

5. From Data Signal to Technical Fix — Three Patterns

The AI tells you what is wrong. It doesn't tell you how to fix it. These three patterns are how you translate a data signal into a surgical Lovable prompt.

Every prompt in this phase starts with "Based on the data showing..." — that's how you stop feature-creeping and start surgically repairing.

🧠 Persona Refinement

When: the data shows users are confused by copy, voice, or framing.

Based on the user data showing [specific metric finding],
refactor all copy in [Screen Name] to the voice of [persona — e.g.
"an efficiency expert"]. Keep all existing functionality and
component structure working. Change only the language.

🔀 Visual Branching

When: the data shows users abandoning a flow — the mental model is wrong.

Based on the user data showing [bounce / drop-off metric] on
[Screen Name], swap the current [component — e.g. "multi-step
wizard"] for [new mental model — e.g. "a single-page Kanban board"].
Preserve the underlying data and submit logic.

🛡️ Guardrail · Hard IF/THEN

When: the data exposes a logic gap — bad data, duplicates, edge cases.

Based on the user data showing [specific failure mode], add a hard
rule: IF [condition], THEN [enforced behaviour]. Show an inline
error if the rule blocks the action. Apply this guardrail to
[specific component / action].

6. The Slack Peer-Feedback Labels

Four labels for the Rapid-Fire Feedback Loop — keep them on the feedback you collect and on the feedback you give back to classmates.

LabelWhat it capturesExample
🐛 A Bug Something broken, not working as intended. "I clicked 'Send Invite' and nothing happened — the form just stayed open."
🤔 Friction Confusion, hesitation, unclear language. "I wasn't sure what 'Track Status' meant — it sounded like it would email me."
🤩 A Compliment What's working — signal the bright spot. "The empty state was so clear — I knew exactly what to click first."
💡 A Feature Idea What would meaningfully extend the product. "It would be great to bulk-import contacts from CSV."

Rule: one labelled comment per peer product. Specific. Tagged. In-thread. Vague "nice app!" is feedback noise, not signal.

One-page mental model

  1. Shift the question: stop asking "what should we build?", start asking "what does the data say?".
  2. The Iteration Mindset (3 levers): Feature Prioritisation · Friction Identification · Hypothesis Validation.
  3. Metrics That Matter: Engagement · Retention · Quality · Impact — 3–5 signals max.
  4. Three Layers of Analytics: Internal (Lovable Insights) · External (GA4) · Custom (Supabase sentiment capture).
  5. The Strategic Prompt: problem + hypothesis + metrics + feedback → ranked backlog.
  6. The Discipline: one finding, one prompt, one redeploy. Not three.
  7. The Patterns: Persona · Branching · Guardrail — every prompt starts with "based on the data showing...".
