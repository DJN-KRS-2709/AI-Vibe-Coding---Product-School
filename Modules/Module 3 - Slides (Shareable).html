A PM's Precision Prompting Toolkit.
Stop describing what you want. Start dictating how it must behave. Vagueness is a bug.
The Prompting Maturity Curve

Connecting precision
with confidence.

Your prompt style should match your certainty. As you learn more about what you're building, your prompts must get more specific.

Exploration Prompts: Open-ended and flexible. Define the "what" through layouts and workflow. You provide the problem and AI suggests the best interaction pattern.
Execution Prompts: Rigid and constrained. Define the "how" through system-grade logic and depth. You dictate exact business rules and edge cases to ensure a professional, reliable demo.

Before the Solution — Three Common Traps

The three traps that trip up even experienced PMs.

Each is solvable with one prompting strategy. Names matter — say them out loud so the room can spot them in their own work.

🧱
The Mega Prompt
The trap: Trying to build the database, the user flow, and the button animations in one massive prompt. If the build fails, you can't tell which part of the prompt caused the collapse.
Fix → Prompt Chaining: build logic first, then design.
🌫️
The "Vague" Request
The trap: Asking for a "Dashboard" without defining the user state or business rules. You get a generic rectangle that breaks the moment a user clicks something unexpected.
Fix → Intentionality: define functionality + path before you hit enter.
🔬
The Micromanager
The trap: Arguing with the AI about hex codes or padding values in text. It burns credits and the AI drifts away from your core logic while it tries to interpret your description.
Fix → Multimodal: don't describe the blue, show the blue.
The Execution Toolkit

Prompt Chaining — three steps, three cognitive strategies.

You aren't just splitting one big prompt into three parts. You're layering different cognitive strategies in sequence so precision accumulates without breaking the foundation.

1
Step 1 · Expand
Build the Logic
Chain-of-Thought (COT)
How — Sequential Multi-Screen Building
Force the AI to build in a strict, dependent order (Screen A → B → C). Use visual references for every new screen to anchor the layout while the prompt anchors the logic.
→
2
Step 2 · Behavior
Define the Flow
Constraint Grounding
How — Constraint Injection
Hard-code if/then triggers for the unhappy path. Ground the AI in specific rules for loading, empty, and error states so it behaves like real software, not a static mockup.
→
3
Step 3 · Refine
Polish the Design
Reflection Prompting
How — Surgical Steering
Isolate a specific screen and force the AI to audit the UI and list gaps before editing. Prevents it from restarting or changing your core logic when you ask for one fix.
The takeaway: COT is how you think within one prompt. Prompt Chaining is the series of prompts you send in order. They operate at different levels — which is why they're used together. Full prompting strategies in the Prompt Techniques Template (link on Resources slide).
Prompt Chaining in Action

What this looks like in three real prompts.

Three prompts. Three strategies. Visual anchors in blue, logic constraints in purple, surgical scope in green.

1 · Expand Sequential Logic (COT)
Build the next phase of this app in a strict sequence: 1. Add a 2nd screen: "User Settings". Match the layout and spacing of the attached Asana reference. 2. Add a 3rd screen: "Account Activity". Match the data-heavy density of the attached Intercom reference. 3. Navigation: write the logic so User Settings links to Account Activity. Build these in order so the Settings screen serves as the mandatory anchor for the Activity view.
Notice: each new screen is tethered to a visual North Star. The prompt handles the "how"; the screenshot handles the "where."
2 · Behavior Constraint Grounding
Apply the following logic constraints to the Account Activity flow: - Use skeleton screens for the transaction list loading state. - If no data is present, show the empty state: "No activity yet. Start your first project to see data here." - On fetch failure, trigger the error state: "Connection lost. Please refresh the dashboard." Maintain the same design language throughout and tether all behavior strictly to these rules.
Notice: exact strings for each state. Hard-coding the unhappy path is what separates a mockup from a product.
3 · Refine Reflection Prompt
The User Settings screen needs a professional Asana-style polish. 1. Start by listing the 3 biggest gaps in typography and spacing compared to the Asana design system. 2. Once you've identified those, resize the headers and update the primary button hex code to match. Don't change anything else in the project or touch the underlying logic.
Notice: audit first, then act. The "Don't change anything else" line is your insurance policy.
Prompt Chain Debugging

"Break It" Mindset — diagnose before re-prompting.

When a chain goes off-rails, throwing more prompts at it just compounds the error. If you're 5+ prompts deep on the same issue, the problem isn't the tool — it's your framing.

STEP 01
📖
Read the Chain
Go back and look at the actual text of your previous 3 prompts. Often you gave the AI a "Never" rule in Prompt 1 that directly contradicts what you're asking for in Prompt 3.
▶
STEP 02
⚖️
Compare the Output
Look at the delta between what you asked for and what was produced. Is the AI failing because it doesn't understand the logic, or because the context is too cluttered?
▶
STEP 03
🔍
Diagnose
Identify the specific point of failure. Did the AI ignore a constraint? Did it lose the thread of the design system? Isolate the one variable causing the drift.
▶
STEP 04
🛠️
Fix It
Revert to the last stable state and re-prompt with a cleaner, more targeted instruction that addresses the specific framing error you identified. Don't just keep going.
The shift: Diagnostic time is not lost time. It's the only way to prevent a total build collapse. As a Senior PM, you stop rage-prompting and move into a diagnostic mindset — your chain stays a precision tool rather than a pile of conflicting instructions.

Key Takeaways

Ensure Complex System Stability with Prompt Chaining

Product Managers must evolve from open-ended exploration to rigid, rule-bound execution as confidence grows. Prompts must shift from defining the "what" to dictating the exact "how" through system-grade logic and depth.

PMs master multi-screen builds by chaining Expand, Behavior, and Refine stages to anchor both layout and logic. Layering constraint injection transforms a static mockup into a functional system that handles real-world failure.

When a chain fails, PMs must stop rage-prompting and diagnose the framing error before attempting a fix. If a build is five prompts deep on one issue, the problem is the underlying framing — not the tool.
