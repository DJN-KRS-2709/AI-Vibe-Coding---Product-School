Rapid-Fire Feedback Loop

Individual Exercise · 10 minutes · runs before Phase 1

Head to #cohort-channel. Test four classmates' deployed products. Leave one structured comment per product. This is the peer signal that fuels Lab 2's AI analysis — and it builds the critical eye you'll turn on your own product in Phase 1.

1
Pick four classmates' URLs
1 minute
From the cohort Slack channel, choose at least four different deployed Lovable links classmates have shared.
2
Test each for ~2 minutes
8 minutes
Sign up with your email, run the core flow, try to break it with edge cases. The goal is detailed feedback you'd want to receive yourself.
3
Leave one structured comment per product
1 minute
Reply in the same Slack thread as the URL was posted. Tag the builder. Pick one of the four labels below — be specific.
🐛
A Bug
"I clicked X and nothing happened — the form just stayed open."
🤔
Friction
"I was confused by the label on the submit button — I wasn't sure what would happen."
🤩
A Compliment
"I was so impressed with the empty-state CTA — I knew exactly what to click first."
💡
A Feature Idea
"It would be cool if this could also import contacts from CSV in bulk."
💬
One labelled comment per peer product. Specific. Tagged. In-thread. "Nice app!" is noise, not signal. Keep your own comments because you'll paste them all into Lab 2's AI prompt later — yours and the ones you receive on your URL.
Comments I received on my URL (collect these for Lab 2)
Paste every comment that lands on your Slack thread — keep the labels (🐛 / 🤔 / 🤩 / 💡) so the AI can weight them.

Run an AI-Driven Iteration Sprint

Individual Lab · 15 minutes

Feed your inputs to an LLM, get a ranked backlog, pick one finding, write one surgical prompt, redeploy. Resist the urge to fix everything.

1
Gather your four inputs
2 minutes
Pull these together in one place before opening your LLM. Saves you context-switching mid-prompt.
Problem statement — one sentence, from your M2 Living PRD. (No PRD? Write it from memory now.)
Hypothesis — your M2 prediction about what users would do.
Lovable Insights metrics — the five values from Phase 1's table.
Peer feedback — every Slack comment on your thread, copy-pasted.
2
Run the Strategic Analysis Prompt
3 minutes
Open ChatGPT, Claude, or Gemini in a new tab. Paste the prompt below, replacing the four [placeholders] with your gathered inputs.
Strategic Analysis Prompt
I built a product to solve this problem: [problem statement]. My hypothesis was: [hypothesis]. Here are the metrics from my deployed product (Lovable Insights): [paste the five-metric block — Visitors, Page Views, Views Per Visit, Duration, Bounce Rate] Here is the feedback I received from peer users in Slack: [paste all peer comments — keep the labels (🐛 Bug, 🤔 Friction, 🤩 Compliment, 💡 Feature Idea) so the AI can weight them] Evaluate honestly: 1. Is this product solving the problem? What does the data actually suggest? 2. Where does my hypothesis appear to be confirmed vs contradicted by the signal? 3. What are the top 3 things I should improve, ranked by likely impact? For each, name the pattern: Persona Refinement / Visual Branching / Guardrail. Be specific and grounded in the data I gave you. Do not invent metrics I didn't share.
💡
The AI is your analyst, not your PM. It will give you a ranked list. You pick the one to ship. Don't outsource the conviction.
3
Pick exactly one finding
2 minutes
From the AI's top 3, pick the single highest-impact recommendation. Not the safest. The one that moves the needle.
My chosen finding
Write the AI's recommendation back in your own words. Include the pattern (Persona / Branching / Guardrail) it maps to.
4
Write your Lovable implementation prompt
2 minutes
Every M6 prompt starts with "based on the data...". Use the matching pattern below for your finding.
🧠
Persona Refinement
When: the data shows users are confused by copy, voice, or framing.
Based on the user data showing [specific metric finding], refactor all copy in [Screen Name] to the voice of [persona — e.g. "an efficiency expert"]. Keep all existing functionality and component structure working. Change only the language.
🔀
Visual Branching
When: the data shows users abandoning a flow — the mental model is wrong.
Based on the user data showing [bounce / drop-off metric] on [Screen Name], swap the current [component — e.g. "multi-step wizard"] for [new mental model — e.g. "a single-page Kanban board"]. Preserve the underlying data and submit logic.
🛡️
Guardrail (Hard IF/THEN)
When: the data exposes a logic gap — bad data, duplicates, edge cases.
Based on the user data showing [specific failure mode], add a hard rule: IF [condition], THEN [enforced behaviour]. Show an inline error if the rule blocks the action. Apply this guardrail to [specific component / action].
My implementation prompt
Write the final prompt you'll paste into Lovable. One change, one component.
5
Run the prompt in Lovable, then test
4 minutes
Paste the prompt. Let Lovable do its thing. Then test the change end-to-end before you redeploy.

Verify before redeploying:

The change works as expected — the friction point the AI flagged is now resolved
Nothing else broke — run your core flow once more (sign-up → main action → check result)
The data in your DB is intact — your prior records still display
🚨
Something broke? Do not redeploy. Re-prompt: "The last change broke [specific thing]. Restore [the working behaviour] while keeping [the new change you wanted]." Ship only when the diff is clean.
6
Redeploy your project
1 minute
In Lovable, click Publish. Your changes are live on the same URL within ~30 seconds.
7
Push your Iteration Sprint Brief to GitHub
1 minute
Commit Iteration-Sprint-Brief.md to 06-iteration/ — the AI analysis, your chosen finding, the implementation prompt, the redeployed URL. The template gives you the structure.

You just closed the loop. Ship → measure → analyse → ship again.
That's the practice. Not the project — the practice.

Build Your Showcase Site

Individual Exercise · 15 minutes · in-class

Your final deliverable is not a PowerPoint. It's a live, hosted showcase site that walks a reviewer through your six modules — Problem · Hypothesis · Validation · PRD · Prompt Chain · Handoff · Friction · Learning · Aha. The Showcase Generator reads your repo's markdown and builds the whole thing for you — no template-editing, no placeholder hunting.

1
Make sure your repo is public
30 seconds
Open your repo on GitHub → Settings → scroll to Danger Zone → Change repository visibility → Public. (GitHub Pages and the generator both need a public repo on the free plan. If you're staying private, paste a personal access token into the generator's optional field.)
2
Drop a STORY.md in your repo
3 minutes
Most learners already have Problem, Hypothesis, Validation, PRD, and Handoff content somewhere in their markdown. What's usually missing: Friction, Learning, and Aha. Copy Templates/STORY-Template.md into your repo as STORY.md and fill in three short paragraphs.
🎯
The bar is your strategic logic, not perfection. Write the Aha section first — that's where most learners under-invest. It should sound like a sentence you'd say at a dinner party, not a deliverable.
3
Open the Showcase Generator & paste your repo URL
2 minutes
Open Templates/Showcase-Generator.html. Paste your repo URL (e.g. https://github.com/you/your-repo) and hit Generate →. The tool crawls every markdown file, matches H2 headers against the 8 showcase slots, and renders the preview live in the page.
4
Fix any yellow placeholder cards
3 minutes
If the generator couldn't find a section, that slide is a yellow card telling you exactly what heading to add (e.g. "Add ## Hypothesis to a markdown file in your repo"). Open the file, add the heading + content, push, and re-run the generator. Loop until every slide is green.
5
Download index.html → drop in docs/
1 minute
Hit ↓ Download HTML in the generator's preview toolbar. Move the downloaded index.html into a docs/ folder in your repo (create it if needed). Commit and push: git add docs/index.html && git commit -m "Add showcase site" && git push.
6
Turn on GitHub Pages from /docs
1 minute
Open your repo on GitHub → Settings → Pages. Under Source, choose Deploy from a branch. Set Branch to main and Folder to /docs. Hit Save. (We use /docs not / (root) so the showcase doesn't collide with your live product's index.html from Lovable.)
7
Verify the public URL
1 minute
Wait ~60 seconds, then refresh the Pages settings page. You'll see a green box with "Your site is live at" followed by https://[your-username].github.io/[your-repo]/. Open that URL in a private browser window to confirm.
Generator filled all 8 sections green — no yellow placeholder cards left
Product link auto-detected in the title slide (your Lovable URL)
Prompt chain populated — at least 1 code block pulled from your prompt-chain markdown
Aha section written like a dinner-party story — not a deliverable
GitHub Pages URL submitted to Docebo
🎉
That's it. Your portfolio is a live URL hosted on GitHub Pages, generated from the same markdown you've been writing across six modules. No PowerPoint, no manual placeholder hunting — just the work itself, rendered. Welcome to the Vibe Coding alumni community. Keep shipping. Keep measuring. Keep iterating.

Connect Google Analytics 4 for the External Behavioural Layer

Lovable Insights is your Layer 1 (internal, passive). GA4 is Layer 2 — deeper funnel signal, traffic sources, conversion paths. ~10 minutes of setup.

1
Create your GA4 account
3 minutes
Go to analytics.google.com → Start measuring. Set: Account name (use your prototype name), Business details, Data collection = Web. Paste your Lovable URL (without https://) into the website URL field.
💡
Click Create and Continue. GA4 generates a screen with your tracking code and a unique Measurement ID starting with G-. Copy it.
2
Connect GA4 to your Lovable project
4 minutes
Paste this prompt into Lovable, replacing G-XXXXXXXXXX with your real ID.
GA4 Connection Prompt
Add Google Analytics tracking to this project. Use Measurement ID: G-XXXXXXXXXX. Add the gtag script to the head of the main HTML file. Track page views automatically. Do not change any existing functionality.
3
Verify in Realtime
3 minutes
Redeploy in Lovable to push the tracking script. Open GA4 → Realtime Overview. Open your live URL in a new tab — you should see yourself appear as an active user. Open it on your phone too — two active users means GA4 is wired up.
GA4 Realtime shows your laptop session
