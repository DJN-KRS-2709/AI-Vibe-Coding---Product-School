The Precision Prompt Chain

The Problem
Your prototype has real data, real user quotes, a design reference, and a real hypothesis. But what happens when your VP asks: "Where's the full flow? What happens when things go wrong?"
You need to prove you could ship this tomorrow.
4 min · Prompt 1
Expand — Architecture Logic
Add 4th and 5th screens with attached visual references (Asana team view, Intercom dashboard). Build navigation across all 5.
4 min · Prompt 2
Behavior — Constraint Grounding
Hard-code loading skeletons, error states for failed invites, empty state for the team workspace. Same design language throughout.

Refine — Surgical Steer
Force the AI to audit its own work first. List 3 gaps in the PM dashboard, then add 'Send nudge' button + hover detail. Don't change anything else.

A documented, reproducible chain — not a series of rebuilds.

02 — SECTION
A PM's Precision Prompting Toolkit
The Prompting Maturity Curve

Connecting Precision with Confidence

Your prompt style should match your confidence level. As you learn more about what you're building, your prompts must get more specific.
UNCERTAINTY → EXPLORATION
Exploration Prompts
Open-ended and flexible. Define the "what" through layouts and workflow. You provide the problem; the AI suggests the best interaction pattern.
CERTAINTY → EXECUTION
Execution Prompts
Rigid and constrained. Define the "how" through system-grade logic and depth. You dictate exact business rules and edge cases for a professional, reliable demo.

Vagueness is a bug. By the end of today, your prompts should look like technical specifications.

Three Common Prompting Traps

What Trips Up Even Experienced PMs

Trap 1
The "Mega Prompt"
Don't try to build a database, API, and UI in one massive prompt. Fix: chain — build logic first, then apply design. If something fails, you know exactly where.
Trap 2
The "Vague" Request
Asking for a feature without defining the user state creates hollow shells. Fix: define functionality and the specific user path before you hit enter.
Trap 3
The "Micromanager"
Wasting credits on text-based pixel tweaks is inefficient. Fix: use multimodal prompting — upload a screenshot of the exact style you want.
The Execution Toolkit

Three Strategies, One Chain

You aren't just splitting one big prompt into three parts — you're layering different cognitive strategies in sequence so precision accumulates without breaking the foundation.
STEP 1 — EXPAND
Build the Logic
Chain-of-Thought (CoT) Prompting
Force the AI to build in a strict, dependent order (Screen A → B → C). Use visual references for every new screen to anchor layout while the prompt anchors logic.
STEP 2 — BEHAVIOR
Define the Flow
Constraint Grounding
Hard-code if/then triggers for the unhappy path. Ground the AI in specific rules for loading, empty, and error states so it behaves like real software.
STEP 3 — REFINE
Polish the Design
Reflection Prompting
Surgical steering — isolate a specific screen and force the AI to audit and list gaps before editing. Prevents drift and protects core logic.

Prompt Chaining in Action

Real Examples of the Three-Step Chain

STEP 1 — EXPAND · CoT PROMPT
Sequential Logic with Visual Anchors
"Build the next phase of this app in a strict sequence: 1. Add a 2nd screen: 'User Settings'. Match the layout and spacing of the attached Asana reference. 2. Add a 3rd screen: 'Account Activity'. Match the data-heavy density of the attached Intercom reference. 3. Navigation: write the logic so 'User Settings' links to 'Account Activity'. Build these in order so the Settings screen serves as the mandatory anchor for the Activity view."
STEP 2 — BEHAVIOR · CONSTRAINT GROUNDING
Hard-Code the Unhappy Path
"Apply the following logic constraints to the 'Account Activity' flow: use skeleton screens for the transaction list loading state. If no data is present, show empty state: 'No activity yet. Start your first project to see data here.' On fetch failure, trigger error state: 'Connection lost. Please refresh the dashboard.' Maintain the same design language throughout and tether all behavior strictly to these rules."
STEP 3 — REFINE · REFLECTION PROMPT
Audit, Then Edit
"The User Settings screen needs a professional Asana-style polish. Start by listing the 3 biggest gaps in typography and spacing compared to the Asana design system. Once you've identified those, resize the headers and update the primary button hex code to match that standard. Don't change anything else in the project or touch the underlying logic."

Prompt Chain Debugging

The "Break It" Mindset — Diagnose Before You Re-Prompt

Throwing more prompts at a broken chain compounds the error. If you're 5+ prompts deep on the same issue, the problem isn't the tool — it's your framing.
01
Read the Chain
Look at the actual text of your previous three prompts. Often a "Never" rule from Prompt 1 is contradicting Prompt 3.
02
Compare the Output
Look at the delta between what you asked for and what was produced. Logic failure or context cluttered?
03
Diagnose
Identify the specific point of failure. Constraint ignored? Design system lost? Isolate the variable causing drift.
04
Fix It
Don't keep going. Revert to the last stable state. Re-prompt with a cleaner, targeted instruction that addresses the framing error.

Diagnostic time is not lost time. It's the only way to prevent total build collapse.

Living Prompt Packs

Your Product Skill File

A Markdown asset that encodes your product's DNA into reusable blocks — and stays portable across tools.
The Anatomy

Four Reusable Pillars

  • Product Context — your source of truth for every new session.
  • Design Reference — visual DNA (Figma link, CSS vars, brand anchors).
  • Constraint Templates — "Always/Never" logic, hard-coded standards.
  • Output Templates — blueprints for components and navigation flows.
The ROI

Precision at Scale

  • Cross-Tool Portability — move between Lovable, Bolt, v0 without losing logic.
  • Guaranteed Reproducibility — anyone runs your pack and gets the same result.
  • Cumulative Precision — every refined constraint becomes a permanent reusable Skill.
