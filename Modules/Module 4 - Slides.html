When Do You Stop Exploring?

Not Every Prototype Should Graduate

The graduation judgment is the most important PM skill in Vibe Coding.
✓ Graduate When
  • The hypothesis is validated (or clearly invalidated)
  • Stakeholders have seen it and said "build this"
  • You can articulate what's real vs. what's mocked
  • The prototype answers a specific question with evidence
✗ Don't Graduate When
  • You're still exploring which direction to go
  • You haven't shown it to anyone outside your team
  • You can't explain the hypothesis it tests
  • The direction could still change fundamentally
⚠️ Watch for Comprehension Debt
After 50+ prompts, the prototype knows more than you do. Signs: you can't describe it without the demo, features you didn't ask for appear, prompts break things that used to work. The Living PRD is your comprehension debt payoff.

Value for Product Managers

Why You Need a Simplified PRD

Vague ideas and prompts lead to weak, unusable prototypes. The Simplified PRD is the translation layer — converting your abstract product vision into a prompt blueprint the AI can execute perfectly.
The Equation
Your Vision (abstract) + Simplified PRD (structured logic) = Executable Prototype

It applies FUDI constraints (Functionality, User flow, Design, Interaction), creates consistency, and makes your build repeatable — answering the core PM question:

📌 PM Question
"How can I validate my idea and get user feedback before I consume engineering resources?"
The Living PRD

A Spec Extracted, Not Imagined

Traditional PRDs are written before anything exists. Living PRDs are extracted from working prototypes. This is Deliverable #3 — it starts today and evolves through M5 and M6.
01
Product Overview
What does this do? Who is it for?
02
Problem & Hypothesis
What's happening today? If we [intervention], then [outcome], because [evidence].
03
User Flows & Screen Map
Screen-by-screen flow. Navigation paths. Edge cases handled.
04
Success Metrics
North star. Leading indicators. Measurement plan.
05
Technical Reality
What's real vs. mocked? What infrastructure is connected?
06
Assumptions & Risks
Confidence levels. Kill switch criteria. What could go wrong.
07
Scope — In vs. Out
What's included, excluded, and phased for later.
08
Engineering Recommendation
Build order. Effort estimates. Open technical questions.

Seven Building Blocks of a Living PRD

Writing for a Code Generator, Not a Committee

🔎
Project Overview — defines the use case (core problem), the goal (measurable outcome), and the target user (persona).
🔃
Inputs and Outputs — a structured table mapping specific inputs (what enters the system) to expected outputs (what the system delivers).
➡️
Ideal User Flow — 3–5 bullet steps outlining the ideal journey from entry to outcome.
🛠️
Core Tools and Stack — the tools, APIs, platforms, or libraries required to build the product.
🧠
Smart Behaviors — decision logic and conditional rules ("If X, then Y") guiding how the system responds.
🚧
Constraints and Edge Cases — technical boundaries, limitations, error states the system must account for.
📝
Light Eval — small test set + defined success criteria (e.g., <1s latency, 90% usability score).

Inputs & OutputsFData Contract — what enters and what leaves.
User FlowUThe Happy Path — sequential steps from A to B.
Core Tools & StackFTech Context — frameworks (React) or APIs that enable the build.
Smart BehaviorsF · IThe Brain — logic and how the system responds to user actions.

Three Superpowers APIs Give Your Prototypes

Why APIs Move the Confidence Line

DYNAMIC CONTENT
Personalization
The Win: transforms a static, generic mockup into an emotionally resonant experience.
Spotify "Discover Weekly" — the API queries your listening history (User ID) to generate a unique playlist, not a global top 40.
REAL-TIME ACTION
Trust
The Win: proves technical feasibility instantly by showing live utility rather than a "fake" animation.
Uber "Driver Tracking" — the API constantly fetches GPS coordinates and updates the car icon in real-time.
MEMORY AND CONTEXT
Continuity
The Win: validates complex cross-platform workflows so the prototype feels smart and polished.
Netflix "Continue Watching" — the API retrieves your specific timestamp so you pick up where you left off.
