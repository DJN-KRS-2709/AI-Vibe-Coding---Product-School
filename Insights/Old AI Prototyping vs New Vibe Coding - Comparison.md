# AI Prototyping (Old) vs. Vibe Coding (New) — Side-by-Side Comparison

> For Carlos. A clear breakdown of what changed, why it changed, and why Vibe Coding is a fundamentally better course.

---

## The One-Line Summary

**Old course:** A Lovable tutorial disguised as a PM certification.
**New course:** A product methodology that happens to use Lovable — students ship real, deployed, data-driven products.

---

## Course Identity

| | AI Prototyping (Old) | Vibe Coding (New) |
|---|---|---|
| **Name** | AI Prototyping Certification | Vibe Coding Certification |
| **Positioning** | Learn to prototype with AI tools | Learn to build, ship, and iterate real products with AI |
| **Audience assumption** | PMs who need to learn AI tools | Senior PMs who need a repeatable methodology |
| **What students leave with** | A group prototype + certificate | A deployed product + Living PRD + GitHub repo + Engineering Handoff Note + Living Prompt Pack + data-driven presentation |
| **Tool dependency** | Course IS the tool tutorial | Course teaches methodology; Lovable is the vehicle |
| **Arc** | Learn prompting → build prototype → present | Uncertainty → confidence → deployed product → learn from it |

## Module-by-Module Comparison

### Module 1

| | Old: Accelerate the Idea-to-Validation Cycle | New: Dive In — Your First Full Cycle |
|---|---|---|
| **Core problem** | Too much intro theory. Students sat through AI usefulness slides they already knew. Instructor demos weren't exciting enough. | Zero theory. Students build in the first 15 minutes. |
| **Structure** | Lecture → instructor demo → group exercise | Instructor demo → students build → share → learn |
| **Hands-on time** | ~30% (students watched more than built) | ~55% (every student builds individually) |
| **Deliverable** | Group notes about AI tools | Individual working prototype + first Living Prompt Pack entry |
| **The "aha"** | "AI tools exist and can build things" | "I just built a working app in 10 minutes" |
| **Why new is better** | Old M1 assumed students didn't know AI existed. New M1 assumes they do and gets them building immediately. Speed confidence on day one. |

### Module 2

| | Old: Write Advanced Prompts for High-Fidelity Prototypes | New: The Validation Lens — Build Smart, Not Just Fast |
|---|---|---|
| **Core problem** | "Too basic for an advanced course." Time wasted on system prompts and token windows. Guessing exercises felt low-value. | Reframed entirely around validation. Not "write better prompts" but "build the right thing." |
| **Focus** | Prompt engineering techniques (FUDI framework, Chain of Thought) | Hypothesis-driven building with Context Data Packs (feedback, metrics, scenario brief) |
| **Lab** | 20-minute prompt exercises (too short, felt artificial) | Full build with real scenario data, Validation Brief, design-matched output |
| **Deliverable** | Improved prompts | Hypothesis-driven prototype with real data context + Validation Brief |
| **Why new is better** | Old M2 taught prompting as a standalone skill. New M2 teaches prompting as a means to validate product assumptions — the actual PM skill. |

### Module 3

| | Old: Define the Modern Specs for Prototype Development | New: Precision Prompting — Build Me Exactly This |
|---|---|---|
| **Core problem** | Confusion between "Simplified PRD" and "PRO." Overwhelming volume of links/docs/templates in first hour. Lacked strategic mindset. | Clean 3-prompt chain pattern. Living Prompt Pack as the reusable artifact. |
| **Focus** | PRD creation and document management | Multi-screen builds, interactive states, documented prompt chains |
| **Lab** | Group template-filling with messy instructions | Individual builds with prompt chains — 5+ screens, states, documented |
| **Deliverable** | Group PRD document | Multi-screen interactive prototype + Living Prompt Pack with full chain |
| **Why new is better** | Old M3 was a document exercise. New M3 is a building exercise where the documentation (prompt pack) emerges from the work, not the other way around. |

### Module 4

| | Old: Build, Iterate, and Debug Prototypes End-to-End | New: From Vibe to Structure |
|---|---|---|
| **Core problem** | "An hour into the class, students still hadn't started building." Gap in advanced debugging. Confusion about Chat vs Agent mode. Students watched instructor build instead of building themselves. | Students connect to real infrastructure (GitHub, Supabase). Living PRD extracted by AI. |
| **Focus** | Debugging and iteration in the tool | Real infrastructure: version control, database connection, Living PRD, engineering handoff |
| **Lab** | Watching instructor debug → attempting own fixes | Students connect their own GitHub repos and Supabase projects, extract Living PRDs |
| **Deliverable** | Debugged group prototype | GitHub repo + Supabase connection + AI-extracted Living PRD + Engineering Handoff Note (started) |
| **Why new is better** | Old M4 taught debugging inside a tool. New M4 teaches the infrastructure transition — from "playing designer" to "building for real." Students own real assets (GitHub repo, database). |

### Module 5

| | Old: Power Advanced Prototypes With API Integrations | New: Make It Real — From Prototype to Product + Deploy |
|---|---|---|
| **Core problem** | API integrations taught abstractly. Students couldn't connect the dots between "integration" and "this works in production." | Three concrete integrations (database, auth, edge cases) + deployment to live URL. |
| **Focus** | API integration patterns | Real database schemas, authentication, error handling, AND one-click deployment |
| **Lab** | Group API integration exercise | Individual: build real database + auth + edge cases + deploy to live URL |
| **The "aha"** | "I can connect to an API" | "My product is on my phone. With a real URL. Anyone can access it." |
| **Deliverable** | Group prototype with API connection | Individually deployed product with real backend + live URL |
| **Why new is better** | Old M5 stopped at "connected." New M5 goes all the way to "deployed." Carlos's exact quote realized: "I can connect to a database. I can push something to production. That would be magic." |

### Module 6

| | Old: Deploy and Scale Prototypes for Production | New: Measure, Learn, Iterate |
|---|---|---|
| **Core problem** | Deployment was the finale but felt anti-climactic — one click. The rest was filler. | Deployment moved to M5. M6 is now the most advanced module: analytics + AI-powered analysis + evidence-based iteration. |
| **Focus** | Deploy + polish + present | Measure (analytics) → Learn (AI analysis) → Iterate (data-driven improvement) + present |
| **Lab** | Deploy (click a button) + polish checklist | 3 labs: Connect analytics, AI analysis sprint, Build one data-driven improvement |
| **The "aha"** | "It's deployed" (already done in new M5) | "AI just analyzed my product data against my problem statement and told me what to fix — in 2 minutes" |
| **Deliverable** | Deployed group prototype + presentation | Analytics-instrumented product + AI-generated analysis + evidence-based improvement + data-driven presentation |
| **Why new is better** | Old M6 was a ceremony. New M6 closes the product lifecycle loop: ship → measure → learn → iterate. This is the skill that separates PMs from builders. |

## Structural Changes That Matter

| Dimension | Old Course | New Course | Why It's Better |
|---|---|---|---|
| **Build format** | Group projects (one person builds, others watch) | Individual builds (every student builds every session) | No more spectators. Every student gets hands-on. Carlos: "It's like showing up to the gym." |
| **Final project** | Group presentation of a group prototype | Individual presentation of a deployed, data-driven product | Students own their work. No dependency on group members. |
| **Tool philosophy** | Course IS the Lovable tutorial | Methodology is tool-agnostic; Lovable is the vehicle | Course doesn't break when Lovable updates. Students can apply to Cursor, Bolt, v0, anything. |
| **Progression model** | Flat (each module teaches a different feature) | Stacking (each module builds ON the previous product) | By M6, students have a single product that evolved across all 6 modules. The five/six-tab reveal makes the progression undeniable. |
| **Artifacts** | Course certificate | 6 tangible deliverables (deployed product, Living PRD, GitHub repo, Handoff Note, Prompt Pack, presentation) | Students leave with a portfolio, not a certificate. They can walk into a stakeholder meeting tomorrow. |
| **Pre-prototyping** | Jump into tool immediately | Context Data Packs, Validation Briefs, Living PRDs before building | Builds are hypothesis-driven, not random. Carlos: "How do you make prototypes look and feel like your existing product?" |
| **Post-prototyping** | Deploy and present | Deploy (M5) → Measure → AI Analysis → Iterate (M6) | Complete product lifecycle. Spotify's "understand it, think it, build it, ship it, tweak it." |
| **Hands-on ratio** | ~30–40% (too much lecture) | ~55–60% per module | Student feedback was clear: more building, less slides. Every module now has 55%+ hands-on. |
| **Instructor consistency** | Instructor-dependent (some skipped labs entirely) | Pre-built demo prototypes + detailed speaker notes + Gamma Prompts + Carlos Briefs | Even a weaker instructor can't skip the hands-on because the entire course is structured around it. |
| **Wow moments** | No deliberate beats | Every module has 2–3 designed wow moments | Carlos: "Every module should come with a wow moment." Each beat is designed, named, and has specific instructor guidance. |

## The Confidence Line (New, Unique to Vibe Coding)

The old course had no unifying arc. Modules were disconnected features of a tool. The new course has the **Confidence Line** — a visual, emotional progression:

| Module | Confidence Level | What Students Can Say |
|---|---|---|
| M1 | Speed | "I can build something in 10 minutes" |
| M2 | Validation | "I can test the right thing" |
| M3 | Precision | "I can build exactly what I describe" |
| M4 | Structure | "I can structure it for a real team" |
| M5 | Ship | "I can make it real and ship it" |
| M6 | Product | "I can learn from it and make it better" |

By M6, students have gone from "I wonder if AI can build things" to "I just shipped, measured, and improved a product." The six-tab reveal makes this visible: open all six versions side by side. The progression speaks for itself.

## Bottom Line

The old AI Prototyping course taught students **how to use a tool**. The new Vibe Coding course teaches students **how to build, ship, and learn from products** — using AI as the accelerant, not the curriculum.

Students leave with a deployed product anyone can access, a spec any engineer can read, a codebase any developer can clone, analytics showing real usage, and a methodology they can apply to their next product tomorrow. That's not a certificate. That's a career skill.
