# Module 6: Measure, Learn, Iterate — Carlos Brief

## TL;DR
M6 is where the product lifecycle closes. Students already deployed in M5 — their products are live. Now they learn from real usage: set up analytics, use AI to analyze data against their problem statement, build one evidence-based improvement, and present the full journey. **The most advanced PM module in the course — not because it's hard, but because it shifts from building to learning.**

## The M6 WOW Moment

**The paradigm shift:** Everything through M5 was about building and shipping. M6 is when students stop building and start learning. The product is already live. Now the question changes: "Is it solving the problem?"

**Beat 1 — The Data Reveal:**
Students open analytics on their deployed product and see real usage data. Page views, sessions, feature usage — data they didn't know was being collected. They're seeing real people using their product. *"People have been using my product and I can see exactly what they did."*

**Beat 2 — AI-Powered Analysis:**
Students feed their metrics + problem statement + hypothesis to ChatGPT or Gemini. In 2 minutes, they get a coherent product analysis: hypothesis confirmed or challenged, patterns identified, improvements ranked by impact. Something that would take a product team a day. *"AI just told me what to fix — and it referenced my original problem statement."*

**The Iteration Close:**
Students build one improvement based on the AI analysis. Redeploy. The live URL now reflects a data-driven decision. That's the full loop: understand → hypothesize → build → ship → measure → learn → improve.

**The Crescendo — Six-Tab Reveal + Presentations:**
M1 → M2 → M3 → M4 → M5 → M6 side by side. The visual arc from one prompt to a deployed, measured, iterated product. Then presentations — students pitch what they built AND what the data told them. The M1 vs M6 side-by-side is the emotional peak: same scenario, six modules of growth.

Two demo moments in M6:

**Demo 1 — Analytics Setup (Slide 3):**
Pull up the deployed Retention Engine. Open Lovable insights — show page views, sessions, feature usage. Then show GA4 dashboard — richer data, real-time view, user flows. "Your product has been live since M5. Did you know this data existed?"

**Demo 2 — AI Analysis (Slide 7):**
Copy Retention Engine metrics + problem statement from Living PRD. Paste into ChatGPT with the analysis prompt. Watch the AI generate a product evaluation in real-time: hypothesis evaluation, pattern recognition, ranked improvements. "That analysis would take a product team a day. You just did it in 2 minutes."

**Total demo time: ~10 minutes.** The analytics demo is straightforward. The AI analysis demo is the beat — let students watch the AI response generate in real-time.

## Student Labs

Students work through three labs plus gallery walk and presentations:

1. **Lab 1: Connect Analytics (15 min):** Review Lovable insights baseline. Set up GA4 (one prompt). Verify tracking — see themselves in real-time view. Screenshot baseline.
2. **Lab 2: AI Analysis Sprint (15 min):** Pull metrics + problem statement + hypothesis. Feed to ChatGPT/Gemini using prompt template. Read AI analysis. Identify single highest-impact recommendation.
3. **Lab 3: Build One Improvement (10 min):** Write iteration prompt based on AI findings. Paste into Lovable. Test. Redeploy. Live URL reflects a data-driven improvement.
4. **Quick Polish (5 min):** Page title, favicon, mobile check. One prompt per fix. Redeploy.
5. **Gallery Walk (20 min):** Open 4–5 classmates' live URLs. Sign up. Try the core flow. Feedback in Slack.
6. **Presentations (30 min):** 5-min pitch: Problem → Hypothesis → Live Demo → What the Data Told You → The Journey. If 20+ students, select 6–8 live. Others post Loom walkthroughs.

**Deliverables:**
- Analytics connected to deployed product
- AI-generated product analysis
- One data-driven improvement, redeployed
- Final Living Prompt Pack export (M1–M6, now including analytics + iteration prompts)
- Finalized Engineering Handoff Note
- 5-minute presentation backed by data

## What Makes M6 Different

### M5 shipped the product. M6 closes the loop.

In M5, the product crossed every threshold: real data, real auth, error handling, live URL. Students shipped. But shipping isn't the finish line.

M6 is where students think like product managers, not builders. The questions change:
- "Is my product solving the problem I defined?"
- "What does the data tell me?"
- "What should I improve, and why?"

This matters because:
- **AI as analyst, not builder** — In M1–M5, AI built things. In M6, AI analyzes things. That's a fundamentally different skill. Students learn to use AI for strategic thinking, not just execution.
- **Evidence over instinct** — Students make one improvement based on data, not a guess. That discipline — data → insight → action — is the core PM skill.
- **Complete product lifecycle** — Understand it, think it, build it, ship it, tweak it. M6 is "tweak it." The course now covers the full Spotify product lifecycle.
- **Students leave with a story, not just a product** — "Here's what I built, here's the data, here's what I improved based on evidence." That's a stakeholder conversation, not a demo.
