M1
Module 1

From theory-first to build-first

Old — Accelerate the Idea-to-Validation Cycle
Too much intro theory. Students sat through AI usefulness slides they already knew. Instructor demos weren't exciting enough.

Structure: Lecture → demo → group exercise
Hands-on: ~30%
Deliverable: Group notes about AI tools
New — Dive In: Your First Full Cycle
Zero theory. Students build in the first 15 minutes. Every student builds individually.

Structure: Demo → build → share → learn
Hands-on: ~55%
Deliverable: Working prototype + Prompt Pack entry
Why it's better: Old M1 assumed students didn't know AI existed. New M1 assumes they do and gets them building immediately. Speed confidence on day one.
M2
Module 2

From prompt tricks to product validation

Old — Write Advanced Prompts for High-Fidelity Prototypes
"Too basic for an advanced course." Time wasted on system prompts and token windows. Guessing exercises felt low-value.

Focus: FUDI framework, Chain of Thought
Lab: 20-min prompt exercises (too short)
Deliverable: Improved prompts
New — The Validation Lens: Build Smart, Not Just Fast
Reframed around validation. Not "write better prompts" but "build the right thing" with real data context.

Focus: Context Data Packs, hypothesis-driven building
Lab: Full build with scenario data + Validation Brief
Deliverable: Hypothesis-driven prototype
Why it's better: Old M2 taught prompting as a standalone skill. New M2 teaches prompting as a means to validate product assumptions — the actual PM skill.
M3
Module 3

From document exercises to building exercises

Old — Define Modern Specs for Prototype Development
Confusion between "Simplified PRD" and "PRO." Overwhelming links/docs/templates. Lacked strategic mindset.

Focus: PRD creation and document management
Lab: Group template-filling with messy instructions
Deliverable: Group PRD document
New — Precision Prompting: Build Me Exactly This
Clean 3-prompt chain pattern. Living Prompt Pack as the reusable artifact. Documentation emerges from the work.

Focus: Multi-screen builds, interactive states, prompt chains
Lab: Individual builds — 5+ screens, states, documented
Deliverable: Multi-screen prototype + full chain
Why it's better: Old M3 was a document exercise. New M3 is a building exercise where the documentation (prompt pack) emerges from the work, not the other way around.
M4
Module 4

From debugging a tool to owning real infrastructure

Old — Build, Iterate, and Debug Prototypes End-to-End
"An hour in, students still hadn't started building." Gap in advanced debugging. Confusion about Chat vs Agent mode. Students watched instructor build.

Focus: Debugging and iteration in the tool
Lab: Watch instructor → attempt fixes
Deliverable: Debugged group prototype
New — From Vibe to Structure
Students connect to real infrastructure. Living PRD extracted by AI. The transition from "playing designer" to "building for real."

Focus: GitHub, Supabase, Living PRD, engineering handoff
Lab: Connect own repos and databases, extract PRDs
Deliverable: GitHub repo + Supabase + Living PRD
Why it's better: Old M4 taught debugging inside a tool. New M4 teaches the infrastructure transition. Students own real assets — GitHub repo, database — not just a prototype file.
M5
Module 5

From "connected" to "deployed"

Old — Power Advanced Prototypes With API Integrations
API integrations taught abstractly. Students couldn't connect "integration" to "this works in production."

Focus: API integration patterns
Lab: Group API integration exercise
Aha: "I can connect to an API"
Deliverable: Group prototype with API
New — Make It Real: From Prototype to Product + Deploy
Three concrete integrations + deployment to live URL. The product is on their phone.

Focus: Database, auth, error handling, AND deployment
Lab: Build real backend + deploy to live URL
Aha: "It's live. On my phone. Anyone can access it."
Deliverable: Deployed product + live URL
Why it's better: Old M5 stopped at "connected." New M5 goes all the way to "deployed." Carlos's exact words: "I can connect to a database. I can push something to production. That would be magic."
M6
Module 6

From ceremony to closing the product lifecycle loop

Old — Deploy and Scale Prototypes for Production
Deployment was the finale but felt anti-climactic — one click. The rest was filler and polish.

Focus: Deploy + polish + present
Lab: Click deploy + polish checklist
Aha: "It's deployed" (now done in M5)
Deliverable: Deployed group prototype
New — Measure, Learn, Iterate
The most advanced module. Analytics + AI-powered analysis + evidence-based iteration.

Focus: Measure → Learn (AI analysis) → Iterate
Lab: 3 labs: analytics, AI analysis sprint, data-driven improvement
Aha: "AI analyzed my data and told me what to fix — in 2 min"
Deliverable: Instrumented product + AI analysis + improvement
Why it's better: Old M6 was a ceremony. New M6 closes the product lifecycle loop: ship → measure → learn → iterate. This is the skill that separates PMs from builders.
Structural Changes

What changed beyond the content

Build Format
Group projects (one person builds, others watch)
Individual builds every session
No more spectators. Every student gets hands-on.
Final Project
Group presentation of group prototype
Individual deployed, data-driven product
Students own their work. Zero group dependency.
Tool Philosophy
Course IS the Lovable tutorial
Methodology-first; tool is the vehicle
Doesn't break when Lovable updates. Transfers to any tool.
Progression
Flat — each module teaches a different feature
Stacking — each module builds ON the previous
One product evolves across all 6 modules. Six-tab reveal.
Hands-On
~30–40% (too much lecture)
~55–60% per module
Student feedback was clear: more building, less slides.
Wow Moments
No deliberate beats
2–3 designed beats per module
Each beat is named and has specific instructor guidance.
Instructor
Instructor-dependent (some skipped labs)
Pre-built demos + speaker notes + Carlos Briefs
Even a weaker instructor delivers the beats.
